# Push画面 モック作成指示

## 目的

EyeG-Stack の Push（メモ作成）画面のHTMLモックを作成する。
API連携は不要。見た目とUXの確認が目的。

## 参照

- デザイン・UI基盤: `eyeg-cal/shared/eyeg.css` を読んで踏襲すること
- カラートークンはEyeG-Stack独自のものをTBDとし、モックでは仮の色（グリーン系など）で実装してよい
- レイアウト構造（`.eyeg-app` / `.eyeg-header` / `.eyeg-main` / `.eyeg-actions`）はシリーズ共通で踏襲する

## 画面構成

### ヘッダー

- 左: アプリ名「EyeG-Stack」
- 右: アバター（ダミーでよい）

### メイン入力エリア（常に表示）

以下の2項目は毎回使う主要項目。大きく・使いやすく配置する。

1. **メモ文**（textarea）
   - プレースホルダー: 「メモを入力…」
   - 最低でも3行分の高さ
   - フォーカス時に自動的にキーボードが上がる想定

2. **カテゴリ**（3択ボタン）
   - 私用 / 仕事用 / 一般
   - 横並びのトグルボタン形式
   - デフォルト選択: 私用

### オプションエリア（折りたたみ or 展開ボタンで表示）

たまにしか使わない項目。初期状態では非表示または折りたたんで、「+ 詳細」などのボタンで展開する。

- **重要度**: 1〜5のスター or 数値ボタン
- **期限**: date picker（`<input type="date">`）
- **写真**: 最大4枚。タップでカメラ/ライブラリ選択（モックではダミーUIでよい）

### GPS

- UIには表示しない。バックグラウンドで現在地を自動取得する想定。
- モックでは「GPS取得中…」などのステータスをフッター付近に小さく表示するだけでよい。

### アクションボタン

- **Push**ボタン（primary）: 画面下部に固定。タップでメモを保存。
- モックではボタンタップ時にアラートなどでフィードバックを返せばよい。

## UX方針

- **手軽さ最優先**: 開いたらすぐ入力できる状態にする。余計なステップを挟まない。
- **オプションは隠す**: 重要度・期限・写真は必要なときだけ出す。デフォルトでは見せない。
- **Pushボタンは常に押せる**: メモ文が空でも送信できる（バリデーションは後回し）。
- タップターゲットは44px以上を厳守。

## 成果物

- `push/index.html`（CSS・JS込みの単一ファイル）
- `eyeg-cal/shared/eyeg.css` を `<link>` で参照してよい（相対パスで `../../eyeg-cal/shared/eyeg.css`）
- テーマカラーは仮でグリーン系（例: `--eyeg-bg-light: #0F6E56`）を使う
