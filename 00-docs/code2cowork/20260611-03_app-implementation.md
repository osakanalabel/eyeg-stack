**日付:** 2026-06-11
**対応指示:** かきざきさんからの直接指示（指示書なし）。「ドキュメントとモックを基に一気に完成させる。VPS 上で docker により nginx + postgres、API は Express。アカウント登録はメールアドレスのみ（二段階なし）、Resend を使用」
**成果物:** `02-app/` 一式（API / フロント / nginx / DB スキーマ / docker-compose）

## 指示通りの実施内容

### 構成（docker 3コンテナ）

- **nginx**: `02-app/web/` の静的配信 + `/api` を Express へリバースプロキシ
- **api**: Express（Node 22 / ESM・ビルド不要）。依存は express / pg / cookie-parser の3つのみ
- **postgres**: 16-alpine。初回起動時に `db/init/01_schema.sql` を自動適用
- `.env` で設定を一元化（`.env.example` 付き）。起動は `docker compose up -d --build`

### 認証 — メールアドレスのみ（マジックリンク）

- `login.html` でメールアドレス入力 → Resend でログインリンク送信（15分有効・1回限り）
- リンク検証成功時に初めてユーザー作成（未確認メールのゴミユーザーを作らない）→ セッション Cookie（30日）
- パスワードなし・二段階なし。Argon2 は不使用（core.md の暫定方針をかきざきさんの指示で差し替え）
- 認証モジュールは疎結合を維持: テーブルは `auth_` プレフィックスで分離、他モジュールへの提供は `requireAuth` ミドルウェアのみ。将来 OAuth 等への差し替え可能
- トークン・セッションとも DB には SHA-256 ハッシュのみ保存（平文トークンを持たない）

### 重みづけアルゴリズム v1.1（03.weight-algorithm.md）

- サーバ側・クエリ時計算の純関数 `weight(memo, ctx)`（`api/src/memos/weight.js`）。weight は保存しない
- S_cat はファジィ版（台形メンバーシップ + 0次 TSK 合成）で実装
- 定数は `api/src/config.js` の `WEIGHT` に一元管理（チューニング表と同名）
- **仕様書の検証値をそのままユニットテスト化し、全件一致を確認済み**（7テスト pass）:
  - 6件ダミーデータの weight（0.716 / 0.517 / 0.241 / 0.200 / 0.200 / 0.193）と並び順
  - 18:00 前後のファジィ遷移値（17:45 work 0.850 など8点）
  - S_man の「3段上げ → 6位から3位」「3週間で寄与半減」
- カウンタ更新（view / manual）では `updated_at` を動かさない実装規則を遵守
- 閲覧カウントは前回閲覧から60分以上のときのみ +1（API 側で `last_viewed_at` 判定）
- 手動順位操作のクランプを実装（モック未クランプ問題の修正。クライアントで実移動可能範囲に、サーバ側でもメモ件数-1 を上限に二重クランプ）

### 画面（モックを本実装化）

- `login.html` / `index.html`（メニュー）/ `push.html` / `check.html` のフラット構成、相互遷移はモックと同じ
- Push: 編集モード（`?id=` でプリフィル・「更新」化）と削除を実装。**削除は Push 側に集約**（effect / output 分離。Check に削除 UI なし）
- 写真: クライアントで長辺1024pxに縮小 → JPEG base64 で送信、最大4枚。一覧クエリでは join せず `GET /api/memos/:id/photos` で個別取得（データモデル方針どおり）
- GPS: バックグラウンド取得、小さなステータス行のみ
- confirm はテーマ済みモーダル（`eyegConfirm`）で統一。ネイティブ alert/confirm 不使用
- 並べ替えドラッグのスクロール干渉（モック申し送り A）: 浮いている間 document レベルで `touchmove` を `preventDefault` する方式で対処（ライブラリ不使用）

## 指示外の追加判断

### 1. `memos.due_at` を TIMESTAMPTZ → DATE に変更

データモデル（02.data-model.md）は TIMESTAMPTZ だが、UI が日付入力であり、重みづけ仕様が「期限日の終わり（23:59:59）を**読み取り時にユーザーTZで**解決する」ため、日付のまま保存するのが最も忠実。TIMESTAMPTZ で保存すると書き込み時の TZ が固定されてしまい仕様と矛盾する。

### 2. users から `login_id` / `password_hash` を削除

パスワードレス化に伴い不要。`email` を UNIQUE NOT NULL に昇格。

### 3. フロントの CSS/JS を共有ファイル化（`web/assets/`）

「モックは単一ファイル自己完結」のルールはモック（01-mock/）のもの。本実装は4画面で同一スタイル・同一部品を使うため、`assets/eyeg.css` / `assets/app.js` に集約した。クラス名・構造は eyeg-cal 由来のものを維持。

### 4. カテゴリ表示名 API（`GET/PUT /api/labels`）

データモデルどおり実装したが、**設定 UI は作っていない**（フィーチャークリープ回避）。フロントは GET でラベルを取得して描画するため、API を叩けばカスタムは反映される。

### 5. メール未設定時のフォールバック

`RESEND_API_KEY` 未設定時はメールを送らず api コンテナのログにリンクを出力（ローカル開発用）。

### 6. Express 5 を採用

当初 Express 4 で組んだところ、async ルートハンドラ内の例外（DB 接続断など）が
プロセスごと落とす問題を動作確認で検出（Express 4 は async の reject を捕捉せず、
Node 22 は未処理 rejection で終了する）。async エラーをネイティブにエラーミドルウェアへ
転送する Express 5 に切り替え、DB 停止状態で 500 応答＋プロセス生存を確認済み。

- **DB スキーマ変更**: `db/init/` は初回起動時のみ適用。以後の変更はマイグレーション手順が必要（README 参照）。
