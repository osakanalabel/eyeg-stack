# Check 詳細モーダルからの削除導線 — フィードバック

**日付:** 2026-08-08
**対応指示:** かきざきさんからの直接指示（指示書なし）。「Push へ遷移してから削除する導線が重い。Check 側から削除できるインターフェースが欲しい」
**成果物:** `02-app/web/check.html`、規約更新（`00-docs/core.md` / `CLAUDE.md`）

---

## 指示通りの実施内容

### 詳細モーダルのフッタに削除ボタンを追加

- メモをタップして開く詳細モーダルのフッタに、既存の編集アイコンと並べてゴミ箱
  アイコンを追加（`[編集][削除][閉じる]` の並び）。
- 押下で `eyegConfirm()` → `DELETE /api/memos/:id` → モーダルを閉じて `refresh()`
  で一覧を再取得。API は既存エンドポイントをそのまま使用しており、サーバ側の追加
  実装はなし。
- アイコン（Feather 系ゴミ箱）・クラス（`.icon-btn--danger`）・確認文言
  （「このメモを削除しますか？」「削除すると元に戻せません。」／`confirmLabel: '削除'`
  ／`danger: true`）は `push.html` の `#delete-btn` と**完全に同一**にした。同じ操作が
  画面によって違う見た目・違う文言になるのを避けるため。
- リストカード側のレイアウト・DOM は一切変更していない。

## 指示外の追加判断

### 1. 詳細モーダルの Esc ハンドラに確認モーダルのガードを追加

詳細モーダルの `keydown` ハンドラと `eyegConfirm()` の `keydown` ハンドラはどちらも
`document` に付くため、確認モーダル表示中に Esc を押すと**両方が反応し、詳細モーダル
まで一緒に閉じる**状態だった。既にライトボックス用に同じ趣旨のガード
（`!document.querySelector('.photo-lightbox')`）が入っていたので、それを
`'.photo-lightbox, .eyeg-confirm'` に拡張して同じ作法で対処した。

### 2. スワイプ削除は採用しなかった

検討はしたが見送った。理由は2点:

- **取り消しが効かない。** `memos` に `deleted_at` は無く、API は物理 `DELETE`
  （`memo_photos` は FK CASCADE）。Google Keep / Gmail のスワイプ削除が成立するのは
  直後の Undo やゴミ箱があるからで、それが無い状態でスワイプを載せると誤爆が即・
  不可逆になる。
- **カードのポインタジェスチャが既に埋まっている。** 長押し 500ms →リフト→ドラッグ
  並べ替えが `document` レベルの `touchmove` 抑止・pointer capture 付きで動いており、
  横スワイプを足すと「縦スクロール / 長押し保持 / 横スワイプ」の軸判定が既存の
  「縦 10px 超で長押しキャンセル」ロジックと衝突する。

将来スワイプを入れるなら、**先に論理削除 + Undo が必要**という整理です。

### 3. 規約ドキュメントを更新

「編集・削除は Check に置かず Push へ遷移」という既存規約に手を入れる変更なので、
`00-docs/core.md` の effect / output 節と `CLAUDE.md` を更新した。位置づけは
**「詳細モーダルは output の延長であり、そこから編集（Push へ遷移）と削除（確定
モーダル）が分岐する」**。カードをタップして詳細を開く明示的な一段があり、削除は
必ず確認を挟むため、effect / output 分離が本来防ぎたい「閲覧していたら不意にデータ
が消えていた」という事故は起こらない、という理由づけです。一覧カード上への直接の
削除操作を置かない点は規約として明記して残しました。

## 申し送り事項

- **姉妹アプリとの作法のズレ**: eyeg-cal は「閲覧側では削除せず別画面へ遷移」の
  ままです。EyeG-Stack だけが詳細モーダル内で削除できる形になったので、シリーズ
  として揃えるかどうかはご判断ください（eyeg-cal は read-only 参照のため、こちらから
  変更はしていません）。
- **論理削除の是非**: 今回は既存の物理削除のまま進めました。「ゴミ箱アイコンだと
  論理削除に見える」という指摘は出ており、現状は確認文言の「元に戻せません。」で
  不可逆性を伝えています。ゴミ箱／Undo を入れる方針であれば、`memos.deleted_at`
  追加 + 一覧クエリのフィルタ + 復元 UI という別スコープの作業になります。
- **未検証**: 実機・ブラウザでの動作確認は未実施です（DB を含む compose 起動が必要な
  ため）。コード上の確認のみで、実際の削除〜一覧再描画は動かしていません。
