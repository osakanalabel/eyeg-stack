## 指示通りの実施内容

### 画面構成

- **ヘッダー**: Push 画面と同じ構造を踏襲。
  - 左: メニューへ（グリッドアイコン → `index.html`）、Push へ（ナビリンク → `push.html`）
  - 中央寄り: アプリ名「EyeG-Stack」＋バージョン `v0.1.0`
  - 右: ダミーアバター「ES」
- **ソートタブ**: ヘッダー直下に横並び3タブ。デフォルト選択は「おすすめ」。
  - おすすめ（重みづけ順）／新しい順（`created_at` 降順）／カテゴリ（私用→仕事用→一般でグループ見出し表示）
- **メモ一覧**: カード形式で縦並び。**カードにはメモ文のみ**表示し、3行で `line-clamp` 省略。カテゴリ・重要度・期限・日時はカードに出さない（シンプルさ優先）。
- **詳細モーダル**: カードタップで下からスライドアップ。
  - メモ文（全文）／カテゴリ／重要度（設定時のみ・★表示）／期限（設定時のみ）／作成日時／写真スロット（ダミー）
  - フッター: 編集 / 閉じる（※削除は撤去。後述 E を参照）
  - 背景タップ・Esc で閉じる
- **Push 導線**: 画面右下にフローティング「＋」ボタン（FAB）。`push.html` へ遷移。

### ダミーデータ

- 指示書のサンプルを基に6件定義。各メモに `manual_up_count` / `manual_down_count` / `view_count` を付与。
- 「おすすめ」タブは `importance` を主軸に手動操作分を加減して上位表示。

### 手動順位操作

- カード**長押し**（`setTimeout` 500ms）で「浮いた」状態（`opacity: 0.8` + 軽い `scale`）。
- ドラッグして離した段数分を `manual_up_count` / `manual_down_count` に加算。
  - 上方向 → `manual_up_count`、下方向 → `manual_down_count`。
- ドラッグ中は他カードがスライドして隙間を作るプレビュー。
- 離した後、簡易重みづけを再計算し「おすすめ」順に即時再描画。

### UX方針・デザイン基盤

- 一覧はメモ文だけのシンプル表示。詳細はモーダルで気軽に開閉。
- FAB で常に Push へ戻れる導線を確保。
- タップターゲットは全て 44px 以上（タブは 36px だが指リーチ十分なサイズで配置）。
- Push 画面（`push.html`）の CSS をコピペ移植して単一ファイルで自己完結。カラートークンも同一（青緑・仮）。

## 指示外の追加判断

### 1. 成果物パスをフラット構成 `01-mock/check.html` に（CLAUDE.md 準拠）

**経緯:** 指示書は成果物を `01-mock/check/index.html`、参照先を `01-mock/push/index.html`（フォルダ構成）と記載。

**決定:** 既存の `push.html` はフラット構成で、そのヘッダーは `href="check.html"` を指している。Push 画面フィードバック #6 で「`01-mock/` 直下フラット構成（index / push / check を相互遷移）」を確定済みのため、本モックも **`01-mock/check.html`** とした。参照する Push 画面も `push.html`、メニューも `index.html` でリンクした。かきざきさん確認済み。

→ **要確認:** 今後の指示書では成果物パスを `01-mock/check.html` 系のフラット表記に揃えていただけると齟齬が出ません。

### 2. 重要度はカードに出さず詳細モーダルのみ（指示準拠の明示）

指示通りカードはメモ文のみ。重要度は詳細モーダル内で★（点灯/消灯）表示にした。

### 3. 並べ替えは「おすすめ」タブのみ有効

**経緯:** 手動カウントは重みづけ順（おすすめ）に効くもの。「新しい順」「カテゴリ」では順位が固定 or グループ化されるため、長押し並べ替えを有効にすると挙動が不自然になる。

**決定:** 長押し並べ替えは「おすすめ」タブ選択時のみ有効化。他タブ選択時は一覧上部のヒント文を「カードをタップで詳細」に切り替え。

### 4. ドラッグ実装は Pointer Events で統一

**経緯:** 指示書は「HTML5 `draggable` またはタッチイベント」。

**決定:** マウス・タッチ双方を1系統で扱えるよう Pointer Events（`pointerdown/move/up/cancel`）で実装。長押し成立前に10px超動いたらスクロール意図とみなしキャンセル。離した直後の `click`（詳細表示）は抑制してドラッグと衝突させない。

### 5. confirm モーダルを Push 画面から移植

削除確認・編集ダミー・閲覧フィードバックに、ネイティブ `confirm/alert` ではなく Push 画面の `eyegConfirm()`（テーマ統一・Promise ベース）を移植。詳細モーダルの上に重ねるため `z-index` を引き上げた。

### 6. 詳細を開くと view_count を簡易加算

閲覧で重みが上がる挙動の雰囲気を出すため、詳細表示時に `view_count += 1`（モックの簡易反映）。

## 実機確認（iPhone SE 相当）後の修正

ブラウザのデベロッパーツールで iPhone SE 表示にして確認し、かきざきさんの指摘を反映。

### A. 並べ替えドラッグがスクロールに引きずられる問題

**現象:** 長押し後ドラッグすると、カードと一緒にページがスクロールしてしまう。

**対応:**
- モック側で `touch-action: none`（浮いた状態）、`pointermove` の `{ passive: false }` + `e.preventDefault()`、`setPointerCapture()` を試した。
- ただしモック上では完全には解消しきれず、**本体実装時に解決する前提で現状は放置**（かきざきさん判断）。並べ替えの挙動自体は本実装でライブラリ等を使って作り直す想定のため、モックでは「長押しで浮く・段数加算される」までの確認用にとどめる。

### B. カテゴリの並び順を「一般 → 仕事用 → 私用」に変更

指示書サンプルは私用先頭だったが、ご指定により `order = { general: 0, work: 1, personal: 2 }` に変更。

### C. 詳細モーダルのフッターを右手操作前提のレイアウトに

**ご指定:** 閉じるは右手で押しやすいところに大きく、編集・削除は小さいアイコンで。

**修正:**
- **閉じる**: primary・大きめ（min-height 52px）でフッター右側（`order: 2`、`flex: 1`）に配置。親指の届く右側に主要アクションを置いた。
- **編集**: 44px 角のアイコンのみボタン（鉛筆 SVG）として左側に小さく配置。
- いずれもタップターゲットは 44px 以上を維持。

> 補足: 当初は「削除（ゴミ箱）／編集（鉛筆）」の2アイコンだったが、後述 E により削除を撤去し、現在は編集アイコン1つ＋閉じるの構成。

### D. 編集ボタンの挙動方針を確定（Push 画面の編集モード再利用）

**経緯:** 編集押下時の処理イメージをかきざきさんと協議。候補は「Push 画面を編集モードで再利用」「詳細モーダル内でインライン編集」「専用 edit.html 新設」の3案。

**決定: Push 画面を「編集モード」で再利用する案で確定。** 理由は EyeG 思想（**Push = effect / Check = output**。データを変える操作＝effect は Push に集約／機能の重複を避ける）に最も忠実なこと、既存の Push フォームをそのまま流用でき実装・保守コストが最小なこと。

- 編集押下 → 確認モーダル → `push.html?id=<memoのid>` へ遷移。
- Push 画面側で `?id=` の有無を見て既存値をプリフィルし、「Push」ボタンを「更新」相当にする想定（Push 側の受け取りは未実装）。
- モックでは遷移までを実装し、プリフィルは未実装である旨を確認モーダルで明示。

> 補足: 「文字直しだけで毎回遷移は重い」体験面の懸念に対し、将来「メモ文だけ詳細モーダル上でインライン編集 → 構造的編集は Push 画面」の二段構えも検討余地あり。今回は A 案単独で確定。

### E. Check の詳細モーダルから削除ボタンを撤去（削除は Push 側へ集約）

**経緯:** Check（output＝閲覧）に削除という破壊的操作を置くのは、EyeG 思想（**Push = effect / Check = output** を混ぜない）に反する。削除はデータを変える操作＝effect なので Push 側が本来の置き場所。eyeg-cal でも「4cal 側では削除せず、2cal 側へ遷移してから削除 UI」という、output 側に effect を置かない作法になっている。

**決定:** Check の詳細モーダルから削除ボタンを撤去。削除は **編集で開いた Push 画面側に集約**（上記 D の編集導線に相乗り）。eyeg-cal の「遷移してから削除」と同じ作法に揃える。

- Check 詳細モーダルのフッターは「編集 / 閉じる」のみ。
- 削除の実 UI は Push 画面（編集モード）側に置く想定。**Push 画面側の削除 UI は未実装**のため、本モックでは Check から削除する手段は無し（編集 → Push 遷移後に削除する流れになる）。

### F. Push / Check の役割を「effect / output」で再定義（思想の確認）

**確認事項:** Push / Check を「入力 / 出力」ではなく **「effect（データを変える作用）/ output（読み取って見せる出力）」** として捉える、とかきざきさんより明確化。

- **Push = effect**: 作成・編集・削除など、メモの状態を変える操作はすべて Push 側。
- **Check = output**: メモを読み取って見せる閲覧専用。
- これにより D（編集 → Push）・E（削除 → Push）の判断が「effect は Push に集約」で一貫して説明できる。

**例外的扱い — 手動順位操作は Check に残す:** 長押しドラッグで `manual_up_count` / `manual_down_count` を加算する操作は、厳密にはカウントを変える effect だが、**「より良く output するための並び調整」**として Check（output）の一部に位置づける（かきざきさん確認済み）。Push へは寄せない。

## 未実装・申し送り事項

- **API 連携なし**: 全データはダミー（メモリ上の配列のみ。リロードで初期状態に戻る）。
- **削除**: Check からは撤去（上記 E）。Push 画面（編集モード）側に置く想定だが、Push 側の削除 UI は未実装。
- **重みづけ**: 本来の weight（カテゴリ×時間帯／重要度／期限近接／view_count／鮮度）はサーバ算出想定。モックでは importance 主軸の簡易式（`importance×10 + (up−down)×5 + view_count`）で代替。
- **並べ替えアニメーション**: ドラッグ中の隙間プレビューは段数概算ベースの簡易表現。実装時はライブラリ（dnd-kit 等）や FLIP での精緻化を推奨。
- **編集**: Push 画面を編集モードで再利用する方針（上記 D）。`push.html?id=` への遷移までモック化済み。Push 側の `?id=` 受け取り・プリフィル・「更新」ボタン化は未実装。
- **並べ替えドラッグ**: モックでは未完成（スクロール干渉が残る）。本体実装時に作り直す前提（上記 A）。
- **写真スロット**: 詳細モーダル内のダミー4枠（🖼/＋）。本実装では別エンドポイントから取得（一覧クエリでは join しない＝データモデル方針どおり）。
- **テーマカラー**: Push 画面と同じ仮色（青緑）。正式色決定時に `:root` 5トークンを差し替え。
