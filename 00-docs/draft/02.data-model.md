# データモデル設計

## DB

PostgreSQL

## テーブル構成

### users

| カラム | 型 | 説明 |
|--------|----|------|
| id | UUID (PK) | ユーザーID |
| login_id | VARCHAR(255) UNIQUE NOT NULL | ログイン用ID |
| password_hash | TEXT NOT NULL | Argon2ハッシュ |
| display_name | VARCHAR(255) | 表示名 |
| email | VARCHAR(255) | メールアドレス |
| last_login_at | TIMESTAMPTZ | 最終ログイン日時 |
| created_at | TIMESTAMPTZ NOT NULL | 作成日時 |
| updated_at | TIMESTAMPTZ NOT NULL | 更新日時 |

---

### category_labels

カテゴリの表示名をユーザーごとにカスタム可能にするためのテーブル。
カテゴリ種別は固定3種（`personal` / `work` / `general`）。

| カラム | 型 | 説明 |
|--------|----|------|
| id | UUID (PK) | |
| user_id | UUID (FK → users.id) | |
| category | VARCHAR(20) NOT NULL | `personal` / `work` / `general` |
| label | VARCHAR(50) NOT NULL | 表示名（例: 私用、仕事用、一般） |

- user_id + category でUNIQUE制約
- レコードがない場合はデフォルト表示名（私用 / 仕事用 / 一般）を使う

---

### memos

| カラム | 型 | 説明 |
|--------|----|------|
| id | UUID (PK) | メモID |
| user_id | UUID (FK → users.id) | 作成者 |
| body | TEXT | メモ文 |
| category | VARCHAR(20) NOT NULL | `personal` / `work` / `general` |
| importance | SMALLINT | 重要度（1〜5） |
| due_at | TIMESTAMPTZ | 期限 |
| latitude | DOUBLE PRECISION | GPS緯度 |
| longitude | DOUBLE PRECISION | GPS経度 |

| last_viewed_at | TIMESTAMPTZ | 最終閲覧日時（閲覧カウントの重複加算防止用） |
| manual_up_count | INTEGER NOT NULL DEFAULT 0 | 手動で順位を上げた累積回数 |
| manual_down_count | INTEGER NOT NULL DEFAULT 0 | 手動で順位を下げた累積回数 |
| last_manual_at | TIMESTAMPTZ | 最終手動操作日時 |

| updated_at | TIMESTAMPTZ NOT NULL | 更新日時 |

### memo_photos

メモと写真の1対多。写真はbase64エンコード済み文字列をtextで保存。
クライアント側で長辺1024pxに縮小してからエンコードして送信する。

| カラム | 型 | 説明 |
|--------|----|------|
| id | UUID (PK) | |
| memo_id | UUID (FK → memos.id) | |
| data | TEXT NOT NULL | base64エンコード済み画像データ |
| order | SMALLINT NOT NULL | 表示順（0〜3） |
| created_at | TIMESTAMPTZ NOT NULL | |

- memo_id + order でUNIQUE制約
- 1メモあたり最大4枚（order: 0〜3）

---

## 設計メモ

- 画像はbase64エンコード文字列としてDB（PostgreSQL TEXT型）に格納する。TOASTにより大容量でも問題なし。
- メモ一覧取得時はmemo_photosを結合しない。画像が必要な場合は個別取得APIを使う。
- カテゴリは`personal` / `work` / `general`の固定3種。表示名のみカスタム可。
- 重要度は1〜5の整数。未設定はNULL。
- 手動操作（上げ/下げ）は累積カウントと最終操作日時をmemosテーブルに保持する。操作ログは持たない（将来必要になれば移行する）。
- 閲覧カウントは前回閲覧（last_viewed_at）から1時間以上空いた場合のみ +1 する。view_count・manual系・last_viewed_at などカウンタ類の更新では updated_at を動かさない（詳細な規則と理由は 03.weight-algorithm.md を参照）。
- 認証モジュールは疎結合。usersテーブルへの依存はFKのみとし、認証ロジックは他モジュールから独立させる。
